# 🔐 Система аутентификации администратора

## ✅ Что реализовано

Система защиты админ-панели через логин/пароль со следующими возможностями:

### 1. API аутентификации

**Файл**: [src/app/api/admin/auth/route.ts](src/app/api/admin/auth/route.ts)

**Методы**:
- `POST /api/admin/auth` - Вход в админку (проверка логина/пароля)
- `GET /api/admin/auth` - Проверка активной сессии
- `DELETE /api/admin/auth` - Выход из админки

**Механизм работы**:
- Учетные данные загружаются из переменных окружения:
  - `ADMIN_LOGIN` (по умолчанию: `admin`)
  - `ADMIN_PASSWORD` (по умолчанию: `admin`)
- При успешной аутентификации создается токен сессии
- Токен сохраняется в httpOnly cookie для безопасности
- Сессия действует 7 дней

### 2. Страница входа

**Файл**: [src/app/admin/login/page.tsx](src/app/admin/login/page.tsx)
**URL**: `/admin/login`

**Возможности**:
- Форма с полями логин/пароль
- Валидация на клиенте
- Отображение ошибок при неверных данных
- Красивый современный дизайн в стиле приложения

### 3. Защита админ-роутов

**Файл**: [src/app/admin/layout.tsx](src/app/admin/layout.tsx)

**Логика**:
- При каждом заходе на любую админ-страницу проверяется наличие активной сессии
- Если сессия не найдена → редирект на `/admin/login`
- Страница `/admin/login` доступна без аутентификации
- Показывается индикатор загрузки во время проверки

### 4. Кнопка выхода

**Компонент**: [src/components/AdminLogoutButton.tsx](src/components/AdminLogoutButton.tsx)

Кнопка добавлена на все админ-страницы:
- ✅ [/admin](src/app/admin/page.tsx) - главная админ-панель
- ✅ [/admin/users](src/app/admin/users/page.tsx) - управление пользователями
- ✅ [/admin/videos](src/app/admin/videos/page.tsx) - управление видео
- ✅ [/admin/trainers](src/app/admin/trainers/page.tsx) - управление тренерами
- ✅ [/admin/shorts](src/app/admin/shorts/page.tsx) - управление Shorts
- ✅ [/admin/reviews](src/app/admin/reviews/page.tsx) - модерация отзывов
- ✅ [/admin/notifications](src/app/admin/notifications/page.tsx) - push-уведомления

## 🚀 Как использовать

### 1. Установка учетных данных

Добавьте в файл `.env`:

```env
ADMIN_LOGIN=admin
ADMIN_PASSWORD=your_secure_password_here
```

**⚠️ ВАЖНО**: Используйте надежный пароль в production!

### 2. Вход в админку

1. Перейдите на `/admin` или любую админ-страницу
2. Вы будете перенаправлены на `/admin/login`
3. Введите логин и пароль
4. После успешного входа вас перенаправит на `/admin`

### 3. Работа с админкой

- Сессия сохраняется в cookie и действует 7 дней
- Вы можете свободно переключаться между страницами админки
- Для выхода нажмите кнопку "🚪 Выйти" в правом верхнем углу

### 4. Выход

- Нажмите кнопку "🚪 Выйти" на любой админ-странице
- Вы будете перенаправлены на `/admin/login`
- Токен сессии будет удален

## 🔒 Безопасность

### Реализованные меры:

1. **httpOnly cookie** - токен недоступен для JavaScript
2. **secure flag** - cookie передается только по HTTPS (в production)
3. **sameSite: lax** - защита от CSRF-атак
4. **Срок действия сессии** - автоматическое истечение через 7 дней
5. **Проверка на каждом запросе** - layout проверяет сессию при загрузке
6. **Переменные окружения** - учетные данные не хранятся в коде

### Рекомендации для production:

1. ✅ Используйте сложный пароль для `ADMIN_PASSWORD`
2. ✅ Настройте HTTPS на сервере
3. ⚠️ Рассмотрите использование базы данных или Redis для хранения сессий (вместо in-memory Map)
4. ⚠️ Добавьте rate limiting для защиты от brute-force атак
5. ⚠️ Рассмотрите двухфакторную аутентификацию для дополнительной безопасности

## 🧪 Тестирование

### Локальная разработка:

1. Убедитесь, что в `.env` есть:
   ```env
   ADMIN_LOGIN=admin
   ADMIN_PASSWORD=admin
   ```

2. Запустите dev-сервер:
   ```bash
   npm run dev
   ```

3. Откройте http://localhost:3000/admin

4. Войдите с логином `admin` и паролем `admin`

### Production:

1. Установите безопасные учетные данные в переменные окружения на сервере

2. Убедитесь, что HTTPS настроен

3. Протестируйте вход/выход

## 🎯 Особенности реализации

- **Client-side проверка** - layout проверяет сессию при каждой загрузке страницы
- **Graceful fallback** - при отсутствии сессии пользователь плавно перенаправляется на логин
- **UX-оптимизация** - индикатор загрузки во время проверки сессии
- **Консистентный дизайн** - кнопка выхода интегрирована в существующий UI всех страниц
- **Переиспользуемый компонент** - AdminLogoutButton используется на всех страницах

## 📌 Примечания

- Сессии хранятся в памяти сервера (in-memory Map)
- При перезапуске сервера все сессии сбрасываются
- Для production рекомендуется использовать Redis или базу данных
